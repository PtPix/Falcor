Deferred Base Pass 技术解析

Base Pass 不产生最终图像，它只回答一个问题：屏幕上每个可见像素，表面是什么、材质是什么。 理解这一点之后，延迟渲染的通道布局、深度预处理、位置重建、格式选择， 都不再是零散技巧，而是同一个约束下的不同取舍。本文按 动机 → 原理 → 公式 → 边界 的顺序拆解。

0全景：一帧的四个阶段

延迟渲染不是一种效果，而是一种求值顺序的重排： 先用廉价的方式确定“谁能被看见”，再把昂贵的材质与光照计算推迟到屏幕空间。

0.1 前向与延迟

前向渲染对每个物体、每个光源，在同一个像素上重复执行“取材质 → 算 BRDF”。 如果屏幕上有 100 个物体互相遮挡，被挡住的表面依然可能先被着色再被深度测试丢弃。 延迟渲染反过来：先只做深度与轻量的表面属性采集，光照则对屏幕上的每个可见像素执行一次。

维度前向延迟
光照求值次数物体 × 光源（含被遮挡）可见像素 × 光源
材质复杂度与光源数相乘与像素数相乘，与光源数无关
带宽低（只写最终颜色）高（写多张 G-buffer）
透明直接支持排序混合需要单独的 Forward 通道
MSAA天然支持带宽成倍增长，通常改用后处理 AA
光源数量线性增长可配合 Tiled / Clustered 批量处理

0.2 Base Pass 的职责边界

Base Pass 只负责采集，不负责积分。它把光照阶段需要的所有输入 写进一组屏幕空间纹理，然后退出。它不应做这些事：

  • 不计算任何直接光或间接光贡献；
  • 不做 Tone Mapping、曝光、Gamma 编码；
  • 不把法线、粗糙度等数据编码成“给人看”的颜色；
  • 不把最终颜色写进材质通道，因为此刻光照尚未确定。
关键分工 Base Pass 的输出是数据，不是图像。任何“看起来像图”的通道（BaseColor、Normal） 都只是恰好可以可视化，它们的数值语义与显示颜色无关。

1可见性：为什么先画深度

延迟渲染要求每个像素只保留最前面的那个表面。先用一个几乎零成本的深度预处理把可见性定下来， 后面的 GBuffer 才能安全地用“深度相等”来筛选片元。

1.1 深度预处理

第一遍只绑定深度缓冲，顶点着色器计算位置，像素着色器为空。它不取材质、不采样纹理， 因此每像素的成本主要是光栅化和深度写入。

第二遍重新提交同一批几何，但深度比较改为相等，且关闭深度写入。 只有与第一遍写下的深度完全一致的片元才会继续执行像素着色器并写 GBuffer。

\[ d_{\text{fragment}} = d_{\text{prepass}} \quad\Longrightarrow\quad \text{write G-buffer} \tag{1.1} \]

这样，GBuffer 的每个像素只会被最前面的表面写一次，后面的表面在深度测试阶段就被拒绝， 不会产生材质采样和多次写带宽。

1.2 过度绘制与 Early-Z

没有预处理时，显卡依赖 Early-Z 在像素着色器之前拒绝被遮挡片元。但 Early-Z 有前提： 像素着色器不能写深度（SV_Depth）、不能丢弃片元（discard）、 不能有 UAV 副作用。一旦材质需要 Alpha Test，Early-Z 往往会被禁用， 大量被遮挡的片元仍会执行昂贵的材质求值。

预处理把“确定可见性”和“执行材质”彻底分开：第一遍允许 Alpha Test 并写深度， 第二遍只处理最终可见的表面。代价是多一次几何提交，收益是避免了材质阶段的过度绘制。

代价与适用范围 预处理并非总是更快。场景简单、过度绘制低、材质便宜时，多一遍几何提交反而增加开销。 它真正划算的场景是：高过度绘制、材质昂贵、大量 Alpha Test 植被。

1.3 两遍一致性

用“相等”筛选的前提是两遍算出的深度逐位一致。这要求：

  • 同一份顶点变换，包括同一组矩阵与同一个 Jitter；
  • 同一份实例变换与顶点变形结果，不能一遍用当前帧、一遍用上一帧；
  • 同样的 Alpha Test 阈值与采样 LOD；
  • 同样的光栅化状态与裁剪规则。

只要有一项不同，就会在轮廓、细几何或动画物体上出现随机漏画。 这也是为什么两遍应当共用同一个顶点变换函数，而不是各写一份。

小结：预处理买的是“材质只对可见表面执行一次”。它的正确性完全依赖两遍深度一致， 而不是依赖深度比较本身。

2深度：投影的副产品

深度缓冲里存的不是距离，而是投影与透视除法之后、经过视口映射的归一化值。 理解这一点，才能解释为什么“深度看起来全白”，以及为什么位置重建必须用同一套矩阵。

2.1 从裁剪空间到设备深度

顶点经过世界、观察、投影变换后得到裁剪坐标 \(p_c\)：

\[ p_c = P \cdot V \cdot p_w = (x_c, y_c, z_c, w_c) \tag{2.1} \]

透视除法得到 NDC，深度方向映射到 \([0,1]\)（Direct3D 约定）：

\[ d = \frac{z_c}{w_c} \in [0,1] \tag{2.2} \]

对右手坐标系、观察空间前方为 \(-z\) 的透视投影，令 \(z\) 为正向观察距离， \(n\) 与 \(f\) 为近远平面，则深度与距离的关系是：

\[ d(z) = \frac{f}{f-n}\left(1-\frac{n}{z}\right), \qquad z \in [n, f] \tag{2.3} \]

当 \(z=n\) 时 \(d=0\)，当 \(z=f\) 时 \(d=1\)。这个式子是非线性的， 而且非线性程度随 \(f/n\) 增大而急剧增加。

2.2 非线性与精度

以 \(n=0.1\)、\(f=100\) 为例：距离 \(1\) 米处深度已经是 \(0.9\)， 距离 \(10\) 米处约 \(0.99\)，两者在 8-bit 显示上都接近白色。 这不是可视化的问题，而是深度本身的分布。

精度问题有两个常见对策：Reverse-Z（近平面映射到 1，远平面到 0，使浮点精度集中在近处）， 以及减小 \(f/n\) 比值。它们改变的是深度分布，不改变“深度不是距离”这一事实。

2.3 为什么不在 GBuffer 存位置

最直接的做法是额外存一张世界位置。但它有三个问题：

  • 带宽：每像素多 8～12 字节，1080p 下就是十几到二十几 MB 的写带宽；
  • 冗余：位置完全可以由深度与相机矩阵唯一确定，存下来是重复信息；
  • 不一致：一旦位置与深度来自不同精度或不同矩阵，阴影、AO、SSR 会出现偏移。

因此成熟管线只在需要时重建位置，并且把重建函数集中到一处， 保证所有下游算法使用同一套约定。

诊断通道 调试期临时输出世界位置是合理的，但它应当是可选的、可断开的。 一旦进入性能测量，这类诊断通道必须从正式布局中移除。

3GBuffer 的本质

GBuffer 不是“把材质存起来”，而是把渲染方程在每个像素上需要的输入， 从几何阶段搬运到屏幕阶段。

3.1 把着色输入冻结到屏幕空间

延迟光照阶段已经看不到三角形、实例和材质对象了，它只有一张张纹理。 因此 GBuffer 必须自包含地回答：

  • 这个像素对应世界上的哪个点？（由深度重建）
  • 它的法线朝向哪里？
  • 它的漫反射反照率、镜面反射率、粗糙度是多少？
  • 它自己发光吗？
  • 它属于哪个实例、哪个材质，供后续 ID 相关算法使用？

这五类信息就是 GBuffer 的最小完备集。世界位置不在其中，因为它可由深度导出； 视角方向也不在其中，因为它由相机位置与重建位置导出。

3.2 带宽账本

延迟渲染的主要成本从“重复着色”转移到了“带宽”。以 1920×1080 估算：

资源每像素1080p 占用
Depth (D32)4 B7.9 MB
GBuffer0 (RGBA8)4 B7.9 MB
GBuffer1 (RGBA8)4 B7.9 MB
GBuffer2 (RGBA16F)8 B15.8 MB
GBuffer3 (RGBA16F)8 B15.8 MB
IDs (RG32U)8 B15.8 MB
合计36 B约 71 MB

这还只是容量，不含 MSAA。若改成 4×MSAA，写入量按样本数成倍增长， 所以延迟渲染通常配合后处理抗锯齿，而不是硬件 MSAA。

带宽守恒：GBuffer 每减少一个字节，都会在光照阶段被读一次。 通道设计的本质是“用多少精度换多少带宽”，而不是“信息越多越好”。

4通道语义

每个通道都应当在文档里有一句无歧义的定义：数值范围、颜色空间、是否线性、由谁消费。 模糊的通道定义会在光照阶段变成难以定位的亮度或高光错误。

4.1 BaseColor

BaseColor 是材质的漫反射基色，在金属工作流里同时承担“金属的 F0 颜色”。 它必须是线性的。常见错误是把它当作已经过 Gamma 的 sRGB 值再参与光照计算， 结果暗部被压暗、颜色偏移。

如果纹理本身是 sRGB 格式，硬件在采样时已经完成解码，着色器拿到的是线性值； 此时不需要也不应该再做一次 pow(2.2)。

用 sRGB 格式的 8-bit 纹理存储线性的 BaseColor 是一种常见优化： 写入时硬件编码，读取时硬件解码，语义仍是线性，但暗部量化误差更小。 代价是任何绕过采样的直接拷贝都会带上编码，必须确保消费方按 sRGB 解码。

4.2 Metallic / Specular / Roughness

金属工作流只暴露两个直观参数：金属度 \(m\) 与感知粗糙度 \(r\)。 光照阶段需要的是介质 F0 与 GGX 的 \(\alpha\)：

\[ F_0 = \mathrm{lerp}\left(0.08\,s,\; C_{\text{base}},\; m\right), \qquad \alpha = r^2 \tag{4.1} \]

其中 \(s\) 是镜面反射标量，默认 \(0.5\)，对应介质 F0 约 \(0.04\)。 把 \(s\) 存进 GBuffer 而不是只存固定 \(0.04\)，是为了保留非默认折射率与艺术化调节。

三个参数对最终外观的作用不同：

  • Metallic 控制漫反射是否存在、F0 是否取基色；
  • Roughness 控制高光 lobes 的宽度与能量分布；
  • Specular 只缩放介质 F0，对金属无效。
不要混用 \(r\) 是感知粗糙度，\(\alpha=r^2\) 才是 GGX 参数。 在 GBuffer 存 \(r\)、在光照阶段平方一次，是唯一不会重复平方的做法。

4.3 Normal

GBuffer 存的是世界空间着色法线，已经包含法线贴图与双面翻转的结果。 它必须是单位向量，但经过插值后长度会变化，因此写入前要重新归一化。

三角面法线（geometric normal）与着色法线（shading normal）不是同一个量。 前者用于背面判断与阴影偏移，后者用于 BRDF。把两者混为一个通道， 会在法线贴图区域产生错误的阴影和 AO。

世界空间法线可以直接存三个分量，也可以压缩成八面体编码的两个分量。 压缩节省带宽，但引入编解码误差，并让调试视图不再直观； 验证阶段应优先保证语义正确，再考虑压缩。

4.4 Emissive 与 IDs

Emissive 是线性 HDR 值，可以大于 1。它不参与 BRDF，也不应被 Tone Mapping。 如果把它 clamp 到 \([0,1]\) 再存储，后续的 Bloom、曝光和 HDR 比较都会失真。

IDs 存实例索引与材质索引，用于材质重排、像素拾取、GPU Driven 管线和虚拟阴影的页请求。 需要区分两种 ID：

类型来源稳定性
运行时索引场景构建后的实例/材质数组下标重新导入或排序后可能变化
稳定 ID资源本身携带的标识，配合映射表跨帧、跨场景可追踪

直接把运行时索引当作稳定 ID，会在场景重载、材质合并、LOD 切换时出现缓存错配。 延迟渲染初期可以先用运行时索引验证通路，但不能把它写进跨帧缓存的键。

5材质如何进入 GBuffer

这一步的难点不是“怎么采样纹理”，而是决定 GBuffer 存的是 作者参数还是光照所需的派生量。

5.1 参数语义与光照语义

材质的原始参数（BaseColor、Metallic、Roughness）是作者语义； 光照真正需要的是漫反射反照率、F0、\(\alpha\)、法线。两者可以互相转换，但转换有损：

\[ C_{\text{diffuse}} = (1-m)\,C_{\text{base}} \tag{5.1} \]

当 \(m=1\) 时 \(C_{\text{diffuse}}=0\)，BaseColor 无法从漫反射反照率反推。 因此“存 BaseColor + Metallic”与“存 Diffuse + F0”是两种不同的信息组织方式， 不是等价的压缩。

  • 存 BaseColor + Metallic：保留作者意图，光照阶段重建 F0；适合材质编辑与调试。
  • 存 Diffuse + F0：直接服务 BRDF，适合固定光照模型；但丢失金属/介质的区分。

两者都能得到正确结果，关键是全管线统一，不允许一个 Pass 按作者语义解释、 另一个 Pass 按光照语义解释。

5.2 常量、纹理与降级

材质参数可能来自常量，也可能来自纹理。统一处理的方式是“带默认值的采样”： 有纹理时采样，无纹理时返回常量。这样 GBuffer 的像素着色器不需要为两种情况写两套分支。

但并非所有材质都能无损映射到同一组通道。遇到以下情况，必须显式标记为“不支持”， 而不是悄悄套用近似：

  • Alpha Mask：需要与深度预处理一致的裁剪，否则边缘会漏；
  • 双面材质：需要按面翻转法线与 F0；
  • 透射、次表面、清漆、毛发：单层 GBuffer 无法表达多层 BSDF；
  • 视差、位移：表面位置与法线不再由几何直接决定。

一个可维护的做法是给 GBuffer 增加一位 shading model / 支持标记， 光照阶段据此选择模型或输出诊断色。降级必须是可见的、可查询的， 而不是“看起来差不多”。

判断标准：如果无法用一个明确的公式说明某个材质如何映射到通道， 就说明它还没有被支持，而不是“近似一下”。

6位置重建

延迟光照、阴影、AO、SSR 都需要世界位置或观察位置。 它们全部由同一张深度图和同一套矩阵导出，这是保证各算法一致性的前提。

6.1 反投影

给定像素 \((x,y)\) 与设备深度 \(d\)，先还原 NDC。注意像素中心偏移与 Y 方向：

\[ u=\frac{x+0.5}{W},\qquad v=\frac{y+0.5}{H},\qquad n_x=2u-1,\qquad n_y=1-2v \tag{6.1} \]

构造裁剪空间齐次坐标，再用当前帧的逆视投影矩阵还原：

\[ h = (VP)^{-1}\,(n_x,\, n_y,\, d,\, 1)^T,\qquad p_w = \frac{h_{xyz}}{h_w} \tag{6.2} \]

观察空间位置与线性深度分别为：

\[ p_v = V\,p_w,\qquad z_{\text{linear}} = -p_{v,z} \tag{6.3} \]

这里的 \(z_{\text{linear}}\) 是沿相机前向的距离，不是到相机的欧氏距离。 两者在画面边缘差异明显，混用会让 AO 半径和雾效距离失真。

6.2 误差来源

来源表现处理
使用未抖动矩阵整体偏移一个亚像素使用生成该深度的同一 VP
像素中心偏移半像素系统偏移统一 +0.5 约定
Y 方向约定上下翻转或镜像集中在一个函数处理
深度精度远处位置抖动控制 \(f/n\)，必要时 Reverse-Z
矩阵转置整体错位或退化固定乘法顺序，单测覆盖

验证重建是否正确，不能只和“另一条 GPU 路径”比较，因为两条路径可能共享同一个错误矩阵。 至少还需要一个独立的 CPU 几何参考：用射线与已知三角形求交，得到解析位置， 再与 GPU 重建结果比较米制误差。

7格式与精度

GBuffer 的每个通道都在做一次精度与带宽的交换。理解量化误差的量级， 才能判断某个偏差是算法错误还是格式限制。

7.1 8-bit 量化

8-bit UNORM 的步长是 \(1/255\approx0.0039\)。对粗糙度而言， \(r=0.05\) 可能被存成 \(0.051\)；对金属度而言，中间值尚可接受， 但接近 0 或 1 的细微差异会被吞掉。

若验收要求精确读取材质参数，应使用 16-bit 格式；若目标是性能， 8-bit 是成熟管线的常态。关键是在文档里写明使用的格式， 否则误差会被误判为 BRDF 实现错误。

7.2 sRGB 往返

线性值写入 sRGB 格式时被编码，采样时被解码。理想情况下往返无损， 实际会引入一次 8-bit 量化，且量化步长在暗部更细。 这对 BaseColor 有利，对 Roughness 这类数据纹理不适用—— 数据纹理不应使用 sRGB 格式。

7.3 半精度

FP16 适合法线与自发光：法线范围 \([-1,1]\)，FP16 的相对精度足够； 自发光是 HDR，FP16 的动态范围远大于 8-bit。 但 FP16 不适合存储世界位置——大世界坐标会因有效位数不足而抖动。

8边界与不适用场景

一个 Base Pass 的价值，一半来自它能正确处理的场景，另一半来自它明确拒绝的场景。

场景单层 GBuffer 的问题常见解法

半透明无法用单深度表示多层Forward 通道、OIT、深度剥离
双面材质法线与 F0 需按面翻转写入前判断正面性

9解码：从通道到 BRDF 参数

GBuffer 里装的不是“颜色”，而是压缩过的作者参数。光照阶段的第一件事不是积分， 而是按约定把它们还原成 \(F_0\)、\(\alpha\)、世界法线这些可以直接代入 BRDF 的量。 这一节把每个 magic number 的来源拆开。

9.1 位布局：一个通道里装了什么

以金属工作流为例，最常见的做法是把四个量塞进一个 RGBA 通道。字段顺序不是通用的， 但语义组合高度一致：

字段范围语义解码后用途
R[0,1]Occlusion / AO环境光遮蔽，不参与直接光 BRDF
G[0,1]Perceptual Roughness \(r\)\(\alpha=r^2\) 代入 GGX
B[0,1]Metallic \(m\)漫反射与 F0 的插值权重
A[0,1]Opacity / 保留与金属度无关

BaseColor 通道则是 RGB 基色加一个 Alpha。这个 Alpha 通常是 opacity， 不是金属度。把 BaseColor.a 当金属度读，是移植材质时最常见的错位来源之一。

某些引擎会把 Shading Model ID 压进某个通道的 Alpha 位，或者单独用一张整数纹理。 无论哪种做法，都要保证：一个字段只表达一个语义，且全管线解释一致。

9.2 Roughness 为什么必须平方

GGX 的 NDF 使用参数 \(\alpha\)，而材质面板给的是感知粗糙度 \(r\)。两者不是同一个量：

\[ \alpha = r^2 \tag{9.1} \]

这个映射来自 Disney 的经验拟合：让高光宽度随滑块变化更接近线性感知。 如果直接把 \(r\) 当 \(\alpha\) 用，低粗糙度区域的高光会过宽， 高粗糙度区域又显得过锐，整体“滑不到想要的位置”。

因此正确的做法是：GBuffer 存 \(r\)，光照阶段平方一次。 存 \(\alpha\) 也可以，但必须在文档里写清楚，否则下游再平方一次就会变成 \(r^4\)。 以 \(r=0.5\) 为例，\(\alpha=0.25\)；若重复平方，\(\alpha=0.0625\)，高光会明显收缩。

GGX 还有一个最小 \(\alpha\) 限制。常见实现取：

\[ \alpha_{\min} = 0.0064 = 0.08^2 \tag{9.2} \]

当 \(r < 0.08\) 时，\(\alpha\) 小于这个值，NDF 的峰值会趋于无穷， 数值上不再稳定。此时通常把材质视为完美镜面，切换到 delta 反射，或者把 \(\alpha\) clamp 到下限。 0.0064 不是随手取的，它是 0.08 的平方；记住这一点， 在别处看到 0.08 时就不会误以为是另一个独立参数。

9.3 F0 的 0.08：一个引擎约定

介质的法向反射率由折射率决定：

\[ f = \frac{n-1}{n+1}, \qquad F_0 = f^2 \tag{9.3} \]

\(n=1.5\) 时 \(f=0.2\)，\(F_0=0.04\)。这就是绝大多数非金属材质默认的 4% 反射率。 注意它是反射率，不是缩放系数。

材质面板通常只暴露一个 0～1 的 Specular 滑块，默认 0.5。为了让 0.5 正好对应 4%， 引擎采用这样一个线性映射：

\[ F_0 = 0.08 \times s \tag{9.4} \]

\(0.5 \times 0.08 = 0.04\)。所以 0.08 是“让 0.5 落在 0.04”的比例因子， 不是物理常数；0.04 才是默认介质的 F0。两者相差一倍，混用会让介质反射率整体偏暗一半。

如果 GBuffer 决定存 Specular 标量而不是直接存 \(F_0\)，就必须约定：

\[ s = \frac{F_{0,\text{dielectric}}}{0.08} \tag{9.5} \]

这样通道里的 0.5 仍然表示 4%，与引擎面板语义一致。反过来，如果直接存 \(F_0=0.04\)， 光照阶段又乘一次 0.08，就会得到 0.0032，材质看起来像塑料蒙了一层灰。

两个数不要互换 0.04 是 F0，0.08 是缩放系数。看到 0.08 * specular 时， 要能立刻反应出“这是在把 0～1 的滑块映射到 0～0.08 的 F0 区间”。

9.4 Metallic 的两次 lerp

金属度同时控制两件事：漫反射是否存在，以及 F0 取介质值还是基色。

\[ C_{\text{diffuse}} = (1-m)\,C_{\text{base}} \tag{9.6} \]
\[ F_0 = \mathrm{lerp}\left(0.08\,s,\; C_{\text{base}},\; m\right) \tag{9.7} \]

两个式子必须同时执行。只做第一个，金属会变成黑色；只做第二个，金属还会保留漫反射， 看起来像蒙了粉尘。

这也解释了为什么 GBuffer 要存 \(C_{\text{base}}\) 与 \(m\)，而不是只存 \(C_{\text{diffuse}}\)： 当 \(m=1\) 时 \(C_{\text{diffuse}}=0\)，基色信息已经丢失，无法再重建金属的 F0。 信息一旦在编码阶段被乘掉，解码阶段就不可逆。

9.5 采样即解码

材质解码的入口通常是“带默认值的采样”。它的语义是： 句柄指向常量时返回默认值，指向纹理时执行采样。 

// 语义：常量走 fallback，纹理走 sample
float4 sampleTexture(handle, sampler, uv, uniformValue, lod)
解码的统一入口：同一段着色器同时支持常量与贴图

这条路径里藏着三个容易忽略的解码约定：

  • sRGB 由格式完成：BaseColor、Emissive 纹理若是 sRGB 格式， 采样时硬件已经解码为线性；着色器里再 pow(2.2) 就是二次解码，暗部会整体变亮。
  • 数据纹理不做 sRGB：Roughness、Metallic、Normal、AO 存的是数值， 不是颜色。用 sRGB 格式存储会让 0.5 被解释成约 0.21，粗糙度整体偏移。
  • 常量本身已是线性：材质面板里的 BaseColor 常量直接以线性值参与计算， 不经过任何传递函数。

LOD 的选择同样属于解码契约。光栅化像素着色器可以用硬件隐式梯度； 光线追踪、延迟光照或 compute 中没有可靠的 2×2 quad，必须改用显式 LOD， 或使用预先存下的 UV 梯度。用错会让纹理在远处出现噪点或过度模糊。

9.6 法线的解码链

法线贴图把方向编码到 \([0,1]\)，第一步是映射回 \([-1,1]\)：

\[ n_t = 2c - 1 \tag{9.8} \]

如果只存了两个分量（RG 编码），第三个分量由单位长度重建：

\[ n_z = \sqrt{1 - n_x^2 - n_y^2} \tag{9.9} \]

然后经切线基变换到世界空间：

\[ n_w = T\,n_{t,x} + B\,n_{t,y} + N\,n_{t,z} \tag{9.10} \]

这里有三个必须遵守的细节：

  • 正交化：插值后的切线不再与法线垂直，需要 Gram-Schmidt 或直接由法线重建切线基；
  • 手性：副切线方向由切线符号决定，符号丢失会导致法线贴图左右翻转；
  • 双面翻转：背面片元必须翻转法线，否则光照会从错误的一侧计算。

如果 GBuffer 存的是世界法线，光照阶段不需要再碰 TBN；如果存的是切线空间法线， 就必须同时保存切线，否则信息不足以还原世界方向。选择哪一种，取决于带宽与下游需求， 但必须在通道定义里写清楚。

9.7 Emissive 与量化

自发光通常是“颜色 × 强度”：

\[ L_e = C_{\text{emissive}} \times k_{\text{emissive}} \tag{9.11} \]

它保持在 HDR 区间，可以远大于 1，并且不参与 BRDF。因此不能用 8-bit UNORM 存储， 也不应该在写入 GBuffer 时 clamp。否则后续的 Bloom、曝光和 HDR 误差比较都会失去依据。

量化方面，FP16 有 10 位尾数，在 \([0,1]\) 区间的相对精度约为 \(5\times10^{-4}\)； 8-bit UNORM 的步长是 \(1/255\approx3.9\times10^{-3}\)，比 FP16 粗一个数量级。 材质常量用 half 存储、GBuffer 用 8-bit 输出，是常见的折中，但误差预算要按最粗的那一环计算。

格式步长 / 相对误差适合存储
FP16约 \(5\times10^{-4}\)法线、Emissive、材质常量
UNORM8\(1/255\approx3.9\times10^{-3}\)BaseColor、Metallic、Roughness
UNORM16约 \(1.5\times10^{-5}\)高精度验收、离线参考
